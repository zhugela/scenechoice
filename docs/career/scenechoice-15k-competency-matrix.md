# SceneChoice × 深圳 15K AI 应用开发能力矩阵

> 目的：项目不是代写代码，而是可验证的就业训练场。

## 总体验收规则

每完成一个模块，负责人必须同时达到五项要求：

1. 说清它解决的业务问题；
2. 读懂核心代码和数据流；
3. 独立完成至少一次小修改；
4. 解释技术选择和替代方案；
5. 回答相关面试追问。

缺少其中任何一项，该模块只能标记为“代码完成”，不能标记为“掌握”。

## 能力映射

| 项目阶段 | 岗位能力 | 必须亲手完成 | 面试证明 |
|---|---|---|---|
| M0 工程底座 | FastAPI、配置、异常、HTTP、测试 | 修改一个接口及对应测试 | 解释 401/403/404、response model、middleware、request ID |
| M1 规划 PoC | LLM API、Prompt、结构化输出、重试 | 调整 Schema/Prompt 并比较结果 | 解释为什么不能信任模型输出、如何处理 JSON 失败 |
| M2 领域与存储 | SQL、ORM、事务、数据建模 | 新增字段并完成迁移和测试 | 解释实体关系、索引、事务和 SQLite/PostgreSQL 取舍 |
| M3 互动引擎 | 状态机、工具调用、权限边界 | 新增一种选择效果和规则测试 | 解释为什么“规则裁决、AI 叙述”更可靠 |
| M4 前后端闭环 | REST、TypeScript、状态管理、错误体验 | 独立联调一个页面流程 | 从浏览器请求讲到数据库和模型响应 |
| M5 质量与发布 | Docker、日志、评测、成本、CI/CD | 定位并修复一个真实反馈问题 | 解释监控指标、Token 成本和线上故障排查 |

## 当前学习状态

|---|---|---|---|
| M0 工程底座 | 已完成 | 部分完成 | 独立复述请求、响应与异常处理链路 |

## 每阶段学习产物

- 一张手绘或 Mermaid 数据流图；
- 一份“我能讲清楚”的模块笔记；
- 一次不看答案的代码修改；
- 五道项目面试题及口述答案；
- 对应 commit、测试结果或演示作为证据。

## 求职完成标准

SceneChoice 达到公开版本只是中间结果。最终目标还要求：

- 项目在线可访问并有真实用户反馈；
- README、架构图、演示和部署说明完整；
- 简历能用数字描述项目结果；
- 能完成 10～15 分钟项目答辩；
- 能独立回答 FastAPI、数据库、LLM、Agent、测试和部署追问；
- 持续投递深圳 AI 应用开发岗位，并根据面试反馈补缺口。
