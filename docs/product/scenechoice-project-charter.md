# SceneChoice 项目立项书 V1.0

> 状态：有条件立项｜负责人：韩立｜基线日期：2026-11-05

## 1. 项目愿景

SceneChoice（幕择）是一个开源 AI 互动短剧引擎。用户输入一句故事灵感，系统生成一部可在 5～10 分钟内完成的 3 集或 5 集短剧，用户的选择会改变人物关系、核心状态和最终结局。

产品口号：**一句话，生成一部由你决定结局的互动短剧。**

## 2. 项目为什么存在

- 普通短剧只能观看，用户不能改变剧情；
- 无限 AI 续写难以收束，常出现人物失忆和逻辑冲突；
- 传统互动作品制作门槛较高；
- 开源社区缺少同时展示结构化生成、状态引擎、一致性评测和可观测性的短剧项目。

## 3. 目标用户与核心任务

### 第一目标用户

喜欢短剧、反转故事和互动剧情，希望在碎片时间参与故事而不是学习创作工具的用户。

核心任务：**给出一句灵感，快速玩完一部选择真正影响结局的短剧。**

### 第二目标用户

学习 Python、FastAPI、LLM 和 Agent 工程的开发者。

核心任务：**运行、理解和复用一个有状态、可测试的 AI 应用工程。**

## 4. MVP 用户旅程

1. 输入一句故事灵感；
2. 选择 3 集或 5 集；
3. 系统生成标题、角色、两个核心状态和剧情大纲；
4. 阅读每集短剧并二选一；
5. 看到选择引起的状态变化；
6. 最后一集进入明确结局；
7. 保存或分享结局卡片。

## 5. 范围

### MVP 范围内

- 一句话灵感输入；
- 3/5 集选择；
- 结构化故事规划；
- 每集两个选择和可验证的状态变化；
- 至少三类结局；
- 故事 ID 与恢复；
- DeepSeek 模型接入；
- Vue 3 + TypeScript 竖屏 Web；
- FastAPI、SQLite、Pydantic、pytest；
- Docker Compose 和公开演示材料。

### MVP 范围外

- 登录、支付和作品社区；
- 无限续写、多人投票和排行榜；
- AI 视频与语音生成；
- 复杂 RAG 和多智能体编剧团队；
- 原生手机 App。

新增想法先进入 Backlog，不直接改变 MVP。

## 6. 核心原则

1. **短**：完整体验控制在 5～10 分钟；
2. **完整**：必须有开端、冲突、反转和结局；
3. **可控**：规则引擎决定事实和后果，AI 负责叙述；
4. **透明**：状态、Prompt、模型耗时和 Token 可观察；
5. **可学**：每个里程碑都必须能由负责人讲清、修改和答辩。

## 7. 技术基线

- 前端：Vue 3、Vite、TypeScript；
- 后端：Python 3.11、FastAPI、Pydantic v2；
- 数据：SQLite，稳定后再评估 PostgreSQL；
- 模型：DeepSeek，封装 OpenAI 兼容适配层；
- 测试：pytest；
- 交付：Docker Compose、OpenAPI、在线 Demo、演示 GIF。

## 8. 成功指标

| 维度 | MVP 验收目标 |
|---|---:|
| 规划 PoC 成功率 | 20 个题材中至少 16 个合格 |
| 首次生成成功率 | ≥ 90% |
| 完整体验率 | ≥ 60% |
| 完整体验时长 | 5～10 分钟 |
| 剧情结构合格率 | ≥ 80% |
| 状态与剧情冲突率 | ≤ 10% |
| 首批真实体验用户 | ≥ 10 人 |
| 新开发者本地启动 | ≤ 10 分钟 |
| 首个公开版本 | 30 Stars、5 条有效反馈、2 个外部 Issue |

Stars 是传播指标，不替代产品质量和真实反馈。

## 9. 里程碑与阶段门

| 阶段 | 交付物 | 通过条件 |
|---|---|---|
| M0 工程底座 | 配置、异常、响应、请求追踪、健康检查 | 自动化测试通过，密钥不入库 |
| M1 规划 PoC | 灵感到结构化故事蓝图 | 20 个题材至少 16 个合格 |
| M2 领域与存储 | Story、Character、Episode、Choice、State、Ending | 数据可保存、恢复，迁移和测试通过 |
| M3 互动引擎 | 选择、状态变更、结局判定 | 后果可验证，AI 不能越权改状态 |
| M4 前端闭环 | 创建、阅读、选择、结局卡片 | 手机浏览器可完整玩通 |
| M5 质量与发布 | 评测、Docker、Demo、README、Release | 10 位真实用户验收并修复关键问题 |

## 10. 风险控制

| 风险 | 控制措施 |
|---|---|
| AI 输出格式错误 | Pydantic 校验、有限重试和降级 |
| 剧情前后矛盾 | 结构化状态、摘要和一致性评测 |
| API 成本失控 | 限制集数/长度、缓存、Token 统计 |
| 生成等待过长 | 分阶段生成、超时和明确加载反馈 |
| 定位同质化 | 坚持短剧、保证完结、状态可视化 |
| 内容安全 | 输入限制、输出审核和测试用例 |
| 范围膨胀 | 立项基线冻结，新增需求进入 Backlog |

## 11. 立项决策

**有条件立项。** M0 保留；在 M1 规划 PoC 通过前，不投入完整前端、社区、RAG 或多智能体功能。

竞品优秀能力采用分阶段融合策略，具体边界见 [`../plans/2026-11-06-scenechoice-competitor-capability-adoption.md`](../plans/2026-11-06-scenechoice-competitor-capability-adoption.md)。该文档不扩大 MVP 范围；发生冲突时，以本立项书的阶段门和范围约束为准。
