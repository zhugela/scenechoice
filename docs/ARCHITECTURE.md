# Architecture

> Scope: M1 (story-planning PoC). M0 foundation is covered inline. Later milestones add persistence (M2), prose generation, player loop, and frontend; those layers are marked "not yet".

## One-line shape

`User inspiration → PromptBuilder → DeepSeekClient (HTTP) → Pydantic schema → BlueprintValidator (rules) → validated blueprint or explicit failure`.

Nothing generated by the model becomes valid until it passes both layers.

## Layers and hard boundaries

```
app/
├── main.py              app factory, middleware, exception handlers, /health
├── middleware.py        request ID (incoming honored, else generated)
├── request_context.py   ContextVar carrying request_id
├── config.py            Settings via pydantic-settings; SCENECHOICE_* env
├── dependencies.py      DI: builds DeepSeekClient + StoryPlanner
├── errors.py            AppError (code, status_code)
├── exception_handlers.py  AppError / HTTPException / RequestValidationError → unified ApiResponse
├── api/
│   └── story_plans.py   POST /api/story-plans/preview (no business validation)
├── services/
│   ├── story_planner.py     orchestration: call → validate → repair → retry
│   └── blueprint_validator.py  cross-field business rules (10 rules)
├── clients/
│   └── deepseek.py      the only place that does HTTP; error classification
├── schemas/
│   ├── story_blueprint.py  Pydantic contracts
│   └── response.py         ApiResponse envelope
└── prompts/
    └── story_planning.py   initial_messages / repair_messages
```

Boundary rules (enforced by reading/review, not yet by a linter):

1. **`app/clients/` is the only layer that makes network calls.** No `httpx`/`requests` below or beside it.
2. **`app/api/` contains no prompt text and no business validation.** It maps request → service call → response/error.
3. **`app/schemas/` holds shape only** (types, enums, ranges, counts). Cross-field story logic belongs in `BlueprintValidator`.
4. **`app/services/` owns business rules.** The planner orchestrates; the validator decides valid/invalid.
5. **Model output is untrusted input.** It is parsed and validated before it can be returned.

## Request flow (preview endpoint)

1. `main.create_app()` wires middleware, exception handlers, router.
2. `middleware.add_request_context` assigns/keeps `X-Request-ID`, stores it in a ContextVar.
3. Pydantic validates `CreateStoryPlanRequest` (FastAPI auto-422 on failure).
4. `StoryPlanner(Dependency)` runs the bounded loop (see `docs/RELIABILITY.md`).
5. Blueprint passes → `StoryPlanPreviewResponse`; failure → `AppError` with an explicit code.

## Data contracts

- `StoryBlueprint`: title, logline, genre, theme, `episode_count ∈ {3,5}`, 2–4 characters, exactly 2 metrics (0–100), episodes matching count, ≥3 endings with conditions + priority.
- `ApiResponse`: uniform `{code, message, data}` envelope for success and errors.
- `AppError`: carries `code` (business) and `status_code` (HTTP).

## Not yet (do not build before the gate)

- M2: domain entities, SQL persistence, migrations.
- Prose generation per episode, player choice execution (rule engine already decides; executor not built).
- Frontend (M6). RAG / multi-agent: explicitly out of M1.
