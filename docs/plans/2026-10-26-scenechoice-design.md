# 幕择 SceneChoice：AI 互动短剧智能体设计

> 状态：已确认｜日期：2026-10-26｜定位：Python AI 智能体应用开发主项目

## 1. 产品定位

幕择是一个有状态的 AI 互动短剧系统。用户输入一句故事灵感并选择 3 集或 5 集，系统生成一部能在 5～10 分钟内完成的短剧。玩家每集做出关键选择，系统根据选择更新真实状态，并生成下一集剧情，最终进入不同结局。

项目不以“让模型随便续写”为目标，而是解决长篇生成中的三个工程问题：人物设定漂移、历史线索遗忘，以及不同选择无法真正改变后续剧情。

后期可扩展直播投票模式，由观众在限定时间内投票决定下一集走向；该功能不属于第一版 MVP。

## 2. 核心流程

```text
创建故事与角色
→ 生成第一集结构化场景
→ 玩家选择行动
→ 加载当前存档
→ 检索相关人物记忆、线索和历史事件
→ 规划下一集剧情
→ 生成结构化场景
→ 一致性校验
→ 执行合法状态变更
→ 保存章节并提供下一组选项
```

## 3. 核心数据

- `Story`：故事名称、题材、世界观、规则和当前章节。
- `Character`：人物目标、秘密、性格、知识边界和存活状态。
- `Relationship`：人物之间的关系、好感度和敌对程度。
- `StoryState`：玩家道具、已发现线索、当前位置和已解锁事件。
- `Episode`：场景、对白、玩家选择、引用记忆和状态变化。
- `Ending`：结局条件、解锁状态和到达路径。

## 4. 智能体与工具边界

第一版采用单智能体的确定性工作流，不做多 Agent。模型可以提出工具调用，但不能直接修改数据库。后端验证目标对象、参数范围、权限和前置条件后再执行。

计划提供的最小工具集：

- `get_story_state`：读取当前故事状态；
- `retrieve_story_memory`：检索相关历史剧情；
- `get_available_clues`：读取玩家已发现的线索；
- `update_relationship`：在合法范围内修改人物关系；
- `grant_item`：根据剧情条件发放道具；
- `unlock_ending`：校验并解锁结局；
- `save_episode`：保存校验通过的新章节。

未知工具、非法人物、越界数值或未满足前置条件的操作必须被拒绝并记录日志。

## 5. 技术路线

- API：Python 3.11、FastAPI、Pydantic v2；
- AI：OpenAI 兼容 SDK、JSON Schema 结构化输出、Tool Calling；
- 数据：第一版 SQLite，稳定后迁移 PostgreSQL；
- 记忆：短期上下文 + 长期剧情摘要与向量检索；
- 工作流：先手写状态机，出现真实分支编排需求后再评估 LangGraph；
- 工程：pytest、结构化日志、请求 ID、耗时与 Token 统计、Docker；
- 交互：先使用 Swagger 或极简 Web 页面，直播投票后置。

## 6. 评测标准

建立固定故事案例，检查：

- 已死亡角色是否错误复活；
- 角色是否获得不应知道的信息；
- 道具或线索是否凭空产生；
- 玩家选择是否导致可观察的状态变化；
- 角色性格和目标是否持续一致；
- 历史伏笔能否被检索并合理回收；
- 输出是否符合结构化 Schema；
- 工具调用是否存在越权、未知工具或非法参数。

## 7. MVP 边界

第一版只支持单个玩家、文本场景、一句话生成故事和每集两个选择。不做视频生成、语音合成、多人实时协作、自动抓取直播内容、多智能体编剧团队或商业支付系统。

完成标准是：用户能够创建一个 3 集或 5 集故事并在 5～10 分钟内到达明确结局；每次选择都产生可验证的状态变化；系统能保存并恢复存档；固定测试覆盖正常、边界和失败路径。正式范围和阶段门以 [`../product/scenechoice-project-charter.md`](../product/scenechoice-project-charter.md) 为准。
