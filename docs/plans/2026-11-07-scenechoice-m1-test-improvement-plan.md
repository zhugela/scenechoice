# SceneChoice M1 测试改进计划

> 来源：2026-11-07 Claude Code 独立测试审查，以及 Codex 对高优先级问题的代码复核。
>
> 原则：先修会造成错误行为或真实网络副作用的问题，再补可靠性与覆盖率；在完成真实 20 题评测前，M1 仍不放行。

## 一、已确认的最高优先级问题

### P1-1：模型认证失败的 API 语义不准确

当前 `DeepSeekClientError` 无论是否可重试、是否为 401/403，都会由故事规划 API 返回 `50201 story model is temporarily unavailable`。

风险：永久性的 Key 失效或权限问题会被描述成临时故障，可能诱导调用方继续重试，也会污染监控分类。

改进：

- 按错误性质区分认证/权限错误和临时模型故障；
- 为永久认证失败补 API 测试；
- 为规划三次失败返回 `42201` 补测试；
- 为 Key 为空字符串或纯空格补 `50301` 测试。

完成标准：上述分支均有明确、稳定的状态码和业务错误码断言。

### P1-2：测试没有隔离本机环境和真实 API

当前部分 API 测试依赖“本机恰好没有配置 DeepSeek Key”。一旦开发者配置 `.env` 或环境变量，测试可能创建真实客户端并访问 DeepSeek。

风险：测试结果随机器变化，可能产生 API 费用，并扩大凭据使用范围。

改进：

- 增加自动使用的测试 fixture；
- 每条测试前后清理 `get_settings()` 缓存；
- 测试默认屏蔽本地 `.env` 和相关环境变量；
- API 测试显式覆盖依赖，禁止意外访问真实网络；
- 真实 DeepSeek 调用只允许出现在明确的 live-eval 命令中。

完成标准：无论本机是否配置 Key，74 个离线测试都不产生网络请求且结果一致。

## 二、第二批可靠性改进

### P2-1：锁定 DeepSeek 请求契约

补充请求体断言：`model`、`messages`、`response_format=json_object`、`temperature`、超时设置。增加可配置的 `max_tokens` 上限及对应测试，避免输出失控造成成本风险。

### P2-2：验证日志可观测性与隐私

成功和失败路径分别验证：

- 日志包含 request ID、模型、尝试次数、耗时和 Token；
- 日志不包含 API Key、完整用户灵感、完整模型输出；
- 失败问题经过截断和脱敏。

### P2-3：加强业务规则测试

- 两个选择的 effects 完全相同时，即使 intent 文案不同，也应按产品定义判断是否属于“同质选择”；
- 增加双指标组合结局的可达与不可达测试；
- 增加 5 集蓝图、不同文本边界和多种 fixture，减少单一样例偏差。

### P2-4：直接测试评测阶段门

- `16/20` 必须通过；
- `15/20` 必须失败；
- 覆盖退出码 0、1、2；
- 覆盖报告落盘、失败原因和模型异常；
- 报告汇总首次成功率、平均耗时和平均 Token。

## 三、第三批覆盖补强

- 参数化覆盖 408、429、500、503 的可重试分类；
- 增加 `DeepSeekClient → StoryPlanner` 的 MockTransport 集成测试；
- 完整断言 API 成功响应的 meta、request ID 和蓝图业务校验；
- 建立 GitHub Actions，在干净的 Python 环境自动运行离线测试；
- 后续增加覆盖率报告，但不把覆盖率百分比当成唯一质量指标。

## 四、明确不混淆的三类验证

| 验证层 | 证明什么 | 当前状态 |
|---|---|---|
| 离线自动化测试 | 代码契约与错误分支没有回归 | 74 条通过，但需先修环境隔离 |
| 20 题真实模型评测 | DeepSeek 输出能否稳定通过结构规则 | 尚未执行 |
| 人工体验评分 | 故事是否好看、选择是否有意义 | 尚未执行 |

自动化测试全绿不等于 M1 验收通过。只有修完 P1、真实评测至少达到 `16/20`、完成人工评分和个人学习验收后，才允许进入 M2 正式开发。

## 五、执行顺序

1. 修复 P1-2 测试隔离，先确保测试永不误用真实 API；
2. 修复 P1-1 错误分流并补齐 API 分支测试；
3. 完成请求契约、日志隐私和评测阶段门测试；
4. 完成业务规则与集成覆盖；
5. 重新执行全量离线测试；
6. 执行真实 20 题评测与人工评分；
7. 更新 M1 验收审计并决定是否进入 M2。

## 六、执行结果（2026-11-07）

- 前五项代码与测试改进已完成；
- 离线测试由 74 条增加到 93 条，结果为 `93 passed`；
- 固定 20 题真实 DeepSeek 结构评测结果为 `20/20`；
- 首次成功率 75%，其余题目由有限修复/重试在三次内完成；
- 人工体验评分仍为 pending，因此 M1 总验收尚未完成。
