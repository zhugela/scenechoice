## 1. 判定口径

M1 的通过条件不是“接口能运行”或“单元测试全绿”，而是同时满足：

1. M1 设计基线中的结构、业务规则、错误处理和可观测性已实现；
2. 固定 20 题真实 DeepSeek 评测至少 16 题通过；
3. 负责人完成代码阅读、亲手修改和口述答辩；
4. 没有把数据库、前端、RAG 或多智能体提前带入 M1。

证据不足一律按未完成处理。

## 5. 错误处理与可观测性核对

已证明：

- 最多三次总尝试，结构问题会带校验反馈重新生成；
- 认证错误立即失败，429/超时/网络/5xx 等可恢复错误才重试；
- 尊重 `Retry-After`，否则指数退避，并限制最大等待时间；
- request ID 可从 HTTP 响应关联到 StoryPlanner 日志；
- 日志记录模型、尝试次数、耗时、Token、失败类型，不记录完整灵感或 API Key；
- API 区分请求错误、规划失败、模型不可用和未配置模型。

已增加由 `httpx.ReadTimeout` 直接触发的客户端测试，证明超时会被转换为可重试的安全错误。

仍需线上确认：

- 等真实调用后确认 DeepSeek 的 Token 字段和 `Retry-After` 行为与假响应一致。

## 6. 测试与评测核对

### 已证明

- 本地 pytest：93 条通过；
- 测试环境隔离本机 `.env` 和 `SCENECHOICE_*`，并禁止离线测试访问外网；
- 固定样例数量为 20，覆盖直播、游戏、悬疑、职场、家庭、情感、校园和科幻；
- 报告保存蓝图、尝试次数、耗时、Token、结构结果与人工评分栏；
- 失败样例不会被报告丢弃。

### 真实模型评测结果（2026-11-07）

- 结构通过率：20/20（阶段门要求至少 16/20）；
- 首次生成成功率：75%（15/20）；
- 第二次成功：4 题；第三次成功：1 题；
- 平均耗时：约 15.3 秒/题；
- 总 Prompt Token：55,873；总 Completion Token：44,269；
- 平均总 Token：约 5,007/题；
- 自动修复曾处理结局优先级重复、非终集缺少悬念；模型临时错误由有限重试恢复。

### 未证明

- 尚未完成人工故事质量评分；
- 结构正确不代表故事足够好玩，仍需检查冲突、选择差异与结局质量；
- 评测报告是本地忽略文件，推送前需保留不含故事正文与密钥的汇总证据。
