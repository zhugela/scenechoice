# SceneChoice · Interactive Drama Planner

## The idea

The user gives one line of inspiration and picks 3 or 5 episodes. At the end of each episode the player makes a choice, a **rule engine** computes relationship and core-state changes deterministically, and the model only narrates facts that are already decided. The story converges to an explicit ending in 5–10 minutes of play.

The interesting engineering is not "call an LLM" — it is **not trusting its output**:

- strict JSON schema plus **cross-field business validation**
- automatic repair loop with **bounded retries** (max 3 model calls) before failing loudly
- a fixed **20-case evaluation set** with a 16/20 gate — the project does not advance on vibes
- failures are observable: invalid output never becomes a valid blueprint

## API

```http
POST /api/story-plans/preview
Content-Type: application/json

{ "inspiration": "a lighthouse keeper who collects lost letters", "episode_count": 3 }
```

Returns a validated blueprint: title, characters, two core states, episode outline and ending conditions. The endpoint is a **preview** — nothing is persisted.

## Design decisions

| Decision | Why |
|---|---|
| Rule engine decides outcomes, LLM only narrates | model creativity is welcome in prose, not in game state |
| Pydantic schema + explicit validator | catches semantic errors (unreachable endings, duplicate ids) that JSON Schema cannot express |
| Bounded repair retries (3) | one bad generation should not fail a whole play session, but infinite retry hides systemic prompt bugs |
| Fixed 20-case eval set | makes regressions measurable instead of anecdotal |
| No database in M1 | keeps the feedback loop short; persistence is an M2 concern |

## Quick start

```bash
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env                                   # fill SCENECHOICE_DEEPSEEK_API_KEY
python -m uvicorn app.main:app --reload                # :8000, docs at /docs
```

```bash
pytest -q                                              # test suite
python evals/run_story_planning_eval.py                # 20-case evaluation
```

## Project structure

```
app/
├── api/            story_plans endpoint
├── clients/        DeepSeek client (retry + timeout)
├── schemas/        Pydantic contracts (blueprint, response)
├── services/       story_planner (generation) · blueprint_validator (rules)
├── prompts/        versioned prompt templates
├── middleware.py   request ID
└── main.py
evals/              20-case eval set + runner
tests/              pytest suite
docs/               product charter, plans, quality gates
```

## Configuration

All settings come from the environment (`SCENECHOICE_*`), validated by `pydantic-settings` at startup. `SCENECHOICE_DEEPSEEK_API_KEY` lives only in `.env` and is never committed — `.env.example` documents the shape with empty values.
